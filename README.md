# dsh-deepseek-web

在 DeepSeek Harness（DSH）现有界面中接入 DeepSeek 网页版。插件把网页版作为**原生右侧栏 Browser 标签页**打开，而不是另造网页容器，因此地址栏、前进/后退、重新载入、标签页拖拽与快捷键都保持 DSH 原有风格。入口是**左侧边栏底部**、设置按钮上方的一个图标：**点一下就是打开**，没有中间菜单。

## 工作方式

DSH 桌面版内置 `@deepseek-ai/dsh-client-ui-sidebar-browser`：桌面配置下用 Electron `<webview>` 承载页面，Web 配置下用带 sandbox 的 iframe。插件不重复实现这部分能力，只做四件事：

1. 在左侧边栏底部动作区（`sidebar.footer.action`）放一个入口按钮，单击即打开（收窄为 56px 图标栏时是圆形图标）；
2. 通过 `ctx.sidebarRight.openTab('browser', { params: { url } })` 放置网页版标签页；
3. 点击时先按**当前屏上会话**查找已有 Browser 标签页，命中则展开右侧栏并聚焦复用，避免每次点击都新建标签而丢失当前对话；
4. 注册快捷键 `Ctrl/Cmd + Alt + D`，并可在配置中开启登录表单自动填入；
5. 允许把网页版里的**会话链接拖到 DSH 的输入框**，插件读到会话 id 后取回该会话正文，以引用形式插入当前输入。

网页版自身的「新对话 / 输入问题 / 查看回复 / 继续会话」全部由网页承载，插件不读取、转发或代理页面内容（拖拽引用除外：只取被拖拽那一个会话的正文）。

| 核心流程 | 承载方式 |
| --- | --- |
| 打开对话 | 点侧栏底部图标（或 `Ctrl/Cmd + Alt + D`）；网页版内点「新对话」 |
| 输入问题 | 网页版输入框 |
| 查看回复 | 网页版页面（含流式输出） |
| 继续会话 | 复用同一会话的 Browser 标签页（`keepMounted` 保留页面状态）；或从网页版历史记录进入 |
| 引用另一段对话 | 在网页版会话列表里把某个会话拖到 DSH 输入框；拖入时窗口底部出现提示，松开后该会话正文作为引用插入 |
| 用某段对话开新会话 | 把会话链接拖到输入框以外的任何位置；松开后官方新建会话入口被调用，正文进入新会话的草稿 |

面板只在有话要说时才出现：首次运行的环境提示，或打开失败时的原因与检查项。正常点击不弹任何浮层。

## 安装与启用

包写在普通工作区目录，不要手工放进 `$DSH_HOME`，也不要改 profile 的 `package.json` 或 `cordis.patch.yml`。

- **GUI**：「插件」→「Add plugin」→ 选择「安装第三方插件」→ 填入插件目录的**绝对路径**。
- **CLI**：`dsh plugin add <插件目录绝对路径>`；指定配置时加 `--profile <name>`。
- **工具**：`plugin_manager` 的 `install_bundle`，`target` 为插件目录绝对路径。

安装后观察 `application` 与 `warnings` 字段判断是否生效。首次安装可经 HMR 激活；若结果为 `restart-required`，或替换了已安装的包，需要重启 DSH。启用后在「插件」列表中应能看到 **DeepSeek 网页版** 及其图标与描述。

`dsh` 未加入 PATH 时，优先使用 GUI 的「Add plugin」或 DSH 会话内的 `plugin_manager` 工具。

自检（离线，不需要启动 DSH）：

```bash
cd <插件目录> && node test/smoke.mjs
```

## 前置条件

| 项 | 要求 |
| --- | --- |
| DSH 版本 | 0.2.2-rc.3 及以上（使用 `sidebar.footer.action`、`mounted`、`tabsIn` 与 `openTab('browser', …)`） |
| 内置 Browser | 桌面配置默认启用；Web 配置默认关闭，需在 profile patch 中写 `- id: ui-sidebar-browser / disabled: false` |
| 右侧栏 | 当前须有前台会话，右侧栏控制器才能放置标签页 |
| 网络 | 能访问 `chat.deepseek.com`；内置 Browser 是真实浏览器导航，不走应用内 web 工具 |

## 配置项

默认值为 `url = https://chat.deepseek.com`、`reuseExistingTab = true`、`registerShortcut = true`、`autoFill = true`、`account = ''`、`password = ''`，由 Host 的 `Config` schema 提供。

**在界面里修改**：「插件」→ 找到 **DeepSeek 网页版** → 进入该包的详情页，描述下方的表单即本插件的配置页。表单直接读写 profile 的配置记录，保存后立即生效，无需重启，也不必手工编辑 YAML。表单包含地址、复用、快捷键、自动填入四个开关类字段，以及账号与密码两个输入框：密码框不回显已保存的值，留空表示保持不变，另有「清除已保存的密码」按钮。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `url` | string | `https://chat.deepseek.com` | 打开的地址；仅接受不含账号密码的 http/https |
| `reuseExistingTab` | boolean | `true` | 当前会话已有 Browser 标签页时聚焦复用；`false` 时每次新建 |
| `registerShortcut` | boolean | `true` | 是否注册 `Ctrl/Cmd + Alt + D` |
| `autoFill` | boolean | `true` | 打开后是否把下面的账号密码填入登录页 |
| `account` | string | 空 | 登录账号（手机号或邮箱），留空则只填密码 |
| `password` | string | 空 | 登录密码；留空则不启用自动填入 |

也可以直接在 profile patch 中按 id 覆盖，**Loader 会整体替换 `config`，需写全字段**：

```yaml
- id: dsh-deepseek-web
  config:
    url: 'https://chat.deepseek.com'
    reuseExistingTab: true
    registerShortcut: false
    autoFill: true
    account: '<你的账号>'
    password: '<你的密码>'
```

`dsh.client.inject` 中列出的 `@deepseek-ai/dsh-client-ui-sidebar-browser` 只用于保证激活顺序，不是依赖声明；这些包由 DSH 安装本体提供，插件不引入 `node_modules`。

## 登录状态与自动填入

- 桌面配置的 Browser 使用进程内会话分区 `dsh-sidebar-browser-<uuid>`，按工作区 CWD 分组：**Cookie 与 Web Storage 不跨 DSH 重启保存**。每次重启应用后需要重新登录，会话历史仍由网页版账号提供。这是内置 Browser 的既定策略，插件不改写，也不尝试绕过站点校验。
- 同一进程内，同一工作区的标签页共享该分区，因此新建标签页不会重复要求登录。
- 设为省去重启后的重复输入，插件可以在打开后把配置里的账号密码键入登录表单并提交：它只填写页面上可见的账号与密码输入框，找到「登录 / Log in / Sign in」按钮时点击一次；页面里没有密码输入框（已登录或尚未加载）时不做任何改动，也不会在多次尝试后反复打扰。

**安全提示**：配置项以明文保存在 profile 的插件配置文件中，任何能读取该文件的人都能看到密码。设置界面用普通文本框显示该字段。若不接受这一取舍，请留空 `password` 并只用手工登录；插件不会读取、导出或上传该值。

## 拖拽引用网页版会话

网页版的会话列表里每个会话都是一个链接，地址形如 `/a/chat/s/<会话 id>`。把它从右侧栏拖到 DSH 界面，插件会：

1. 从拖拽携带的标准文本里取出会话 id（跨 frame 拖拽只传标准类型，插件也不依赖自定义 MIME）；
2. 在承载网页版的那个 `<webview>` 内调用站点自己的读接口 `/api/v0/chat/history_messages`，带上访问者本机的登录态；
3. 抽出 `REQUEST` 与 `RESPONSE` 片段，拼成「用户 / 助手」交替的文本，然后按落点分流：

| 落点 | 结果 |
| --- | --- |
| 输入框（输入胶囊）内 | 用官方 `inputActions.insertQuote` 把正文作为引用插入当前会话的输入框 |
| 输入框以外 | 用官方 `uiWorkspace.startSession` 开一个新会话，正文写进它的草稿 |

拖入过程中在窗口底部浮出一行提示（覆盖层，不参与输入框布局），文案随指针位置切换为「引用到输入框」或「新建对话」；松开后给出结果并附上具体原因。正文超过 12000 字符时截断并标注省略。整个过程只在本机完成：不向任何第三方发送数据，也不调用站点以外的主机。

读取时会带上网页版自身的客户端标识头，并在站点把令牌包成对象时先解包再使用；若令牌被拒则回退为仅凭登录 Cookie 重试一次。

- 只读取被拖拽的那一个会话，不批量抓取、不写回站点。
- 页面未登录或会话已删除时无法读取，提示里会写明是哪一步失败（无网页视图、HTTP 状态、业务码、无内容等）。
- 新建会话走官方入口：目标工作区取当前会话所属的工作区，没有则取最近活动的；若该工作区已有空会话，官方会复用它而不是再建一个；一个工作区都没有时无法新建，提示里会说明。
- 仅桌面配置生效：Web 配置下没有 `<webview>`，拖拽不会取回正文。

## 首次运行提示

首次点开入口时，面板会展开并显示一条「环境提示」：DeepSeek 网页版运行在内嵌浏览器里，站点可能报告环境异常并建议使用官方客户端；插件仅在本机打开该页面，不读取或转发对话内容。点「不再提示」后写入本地存储，之后不再出现。

- 提示只解释与引导，不拦截打开操作，也不改变站点行为。
- 本地存储不可用时（例如受限的存储策略）提示保持隐藏，避免每次启动重复打扰。

## 错误提示

状态显示在入口展开后的面板内；出错时给出可读文案、重试按钮与检查项。页面自身的加载失败由内置 Browser 的原生失败提示负责，两者互补。

| 状态 | 触发条件 | 提示 |
| --- | --- | --- |
| `no-service` | 右侧栏服务未就绪 | 右侧栏服务未就绪，无法打开标签页 |
| `no-browser` | `openTab('browser')` 因未注册该类型而抛错 | 提示在「插件」中启用 `dsh-client-ui-sidebar-browser`；Web 配置还需 `disabled: false` |
| `no-session` | 无前台会话，右侧栏无法放置标签页 | 进入一个会话后重试 |
| `bad-url` | 配置地址为空、超长、协议非 http/https、含账号密码或无法解析 | 显示具体原因，仅接受合规地址 |
| `open-failed` | 打开时抛出其它异常 | 显示异常摘要，提示检查右侧栏 |
| 页面级失败 | DNS、TLS、CSP、`X-Frame-Options`、白屏、登录失效 | 由内置 Browser 的加载失败提示显示；面板提供「重试」与检查项 |

所有服务调用均包在 `try/catch` 中，Client 半部不抛异常拖垮所在 bundle；快捷键在没有可见组件时也会把错误写入控制台。

## 适用边界

- 适用于桌面配置的 DSH 0.2.2-rc.3 及以上；Web 配置需先启用内置 Browser，且页面受 iframe sandbox 限制更多。
- 面向「在 IDE 内随时切到网页版对话」的场景；不改变 DSH 自身的 Agent 会话、工具、提示词或模型请求，不注册模型可见能力。
- 网页版与 DSH 会话相互独立：网页里的对话不会进入 DSH 的会话日志，也不会消耗 DSH 的模型额度。
- 站点需允许在 `<webview>` / iframe 内加载；只允许 http/https，拒绝 `file:`、脚本/数据地址、内嵌凭据与应用自身 origin。

## 已知限制

1. **登录态不跨应用重启**：桌面 Browser 分区为进程内分区，重启后需重新登录。配置账号密码后可由插件自动填入，但这只是省略输入步骤，不等于恢复会话。
2. **自动填入依赖页面结构**：登录表单由站点渲染，字段与按钮的识别基于可见输入框类型与按钮文案；站点改版、验证码、二次验证或非标准登录页可能使填入无效，此时仍需手工登录。
3. **部分站点拒绝嵌入**：CSP 或 `X-Frame-Options` 可能导致空白页；浏览器出于安全考虑常不派发可识别的 `error` 事件，加载失败提示是尽力而为。此类情况应使用 Browser 工具栏的「在系统浏览器打开」。
4. **页面内部状态不可观测**：受同源策略与 webview 隔离限制，插件无法判断网页是否已完成登录、是否正在流式输出或是否报错；这些状态由网页版自身呈现。
5. **下载、原生弹窗、权限请求被拒绝**：内置 guest 策略统一禁用，需要这些能力的操作应转到系统浏览器。
6. **地址变化不可完全追踪**：网页内部 History API 与 fragment 跳转不产生新的导航记录；插件只按「当前会话是否有 Browser 标签页」复用，不推断页面 URL。
7. **Web 配置的 sandbox**：默认 sandbox 会限制顶层跳转与下载；取消 sandbox 只对当前标签页临时生效。Web 配置下没有 `<webview>`，自动填入不生效。
8. **快捷键冲突**：`Ctrl/Cmd + Alt + D` 可能被系统或其它应用占用，可设 `registerShortcut: false` 关闭，只用按钮入口。
9. **侧栏底部空间有限**：`sidebar.footer.action` 渲染在设置按钮上方，与面板列表（「插件」「自动化任务」「更多」）同处侧栏底部，条目较多时该区域会被压缩；插件按 42px 行高与 36px 圆形按钮（收窄栏）渲染，不参与折叠逻辑。
10. 未在 Web 配置与 macOS/Linux 上做实机验证；`openTab`、`focus`、`tabsIn`、`mounted` 的行为来自 DSH 0.2.2-rc.3 桌面版源码。
11. **拖拽依赖站点接口与页面结构**：会话地址形如 `/a/chat/s/<id>`，正文来自站点的 `/api/v0/chat/history_messages`；站点改用其它路由或接口、或页面已登出时，拖拽会提示无法读取，并在提示里带上失败的具体原因。只在拖动会话**链接**时生效，拖动纯文本不会触发。新建会话走官方入口，其失败（无工作区、被目标会话拒绝等）只体现在 DSH 自身的提示里。
12. **拖拽监听挂在会话作用域上**：没有前台会话时（例如停在欢迎页）没有可挂载的位置，此时拖拽既不出提示也不生效；先进入任意会话即可。

## 卸载

在「插件」中移除该 bundle，或使用 `plugin_manager` 的 `remove_bundle`。插件不写应用配置之外的数据；卸载后启动入口、快捷键与标签页类型登记一并消失，已打开的 Browser 标签页属于内置功能，不受影响。
